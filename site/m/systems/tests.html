The bug no assertion catches

A renderer's characteristic failure is not a crash. It is a frame three percent too dark, a highlight that lost its anisotropy, a sampler that stopped decorrelating. Nothing in the C++ is invalid, so nothing asserts; the only oracle is the image. OHAO's top-level test is therefore a rendered PNG diffed against a committed one, and every decision here lives inside *diffed*.

Determinism had to be bought before it could be tested

You cannot diff renders that are not reproducible, and OHAO's were not. The offline reference raygen's temporal reprojection sampled the accumulation buffer at a *reprojected neighbour* pixel — a texel that sibling invocations of the same dispatch write at the end of the very same shader. That is a cross-invocation read-after-write with no defined ordering, so a static scene did not render the same way twice.

// Phase 0 determinism contract: temporal reprojection reads accumBuffer at ashaders/rt/pt_raygen_offline.rgen:1217

The fix is one assignment forcing the own-pixel accumulation branch; the offline camera never moves, so reprojection bought nothing. The block below it was left in place, merely unreachable. With it off, repeat renders of one frame differ by at most ~6 pixels at 1 LSB on a 1920×1080 frame: the irreducible floor from non-associative reduction order in the multi-light NEE sum.

"6.2M by 1 LSB between sessions; 4 covers that with margin."tests/golden/manifest.json:29
Why

Bit-exact hashing was rejected because it would flag that six-pixel ghost forever. True bit-exactness means forcing reduction order and disabling fast-math — real effort and real performance cost to close a six-pixel gap. A tolerance compare absorbs the floor while still catching anything real, the same call PBRT and Mitsuba's suites make.

Two predicates, because one is not enough

A scene passes only if both conditions hold:

$$ \max_{p,c} \bigl|A_{pc} - G_{pc}\bigr| \le \tau_{\text{abs}} \qquad \wedge \qquad \frac{\bigl|\{\, p : \exists c,\; A_{pc} \neq G_{pc} \,\}\bigr|}{|P|} \le \tau_{\text{frac}} $$

$A$ is the fresh render, $G$ the committed golden, both 8-bit sRGB after the downscale below; $P$ is the pixel set of that reduced grid and $c$ the channel. Defaults are $\tau_{\text{abs}} = 4$ LSB and $\tau_{\text{frac}} = 0.01$, overridable per scene from the manifest.

def verdict(s, max_abs_diff, max_diff_frac):tests/golden/render_golden.py:137

The two fail on opposite regressions. The max catches a localized, high-magnitude change — one light missing, one material black — which can touch well under 1% of pixels. The fraction catches the inverse: an exposure or tonemap constant shifting every pixel by one LSB, which sails under the max. Note the membership test is $\neq$, not a threshold, so a pixel counts as differing on a single LSB; the 1% budget absorbs that hair-trigger.

Both statistics are computed on `int16`. On the natural `uint8` the subtraction wraps, and a golden one LSB *brighter* than the render reads as a difference of 255 instead of 1 — catastrophic failure on a perfect match.

return np.asarray(downscale(Image.open(path).convert("RGB")), dtype=np.int16)tests/golden/render_golden.py:121

The downscale that does two jobs

Before diffing, both images are bilinearly resized to 640 pixels wide; the manifest scenes render at 1920×1080, so the goldens on disk are 640×360.

DOWNSCALE_WIDTH = 640 # compare at reduced res: averages the FP ghost away + tiny goldenstests/golden/render_golden.py:36

That step pays twice: it averages the floating-point ghost down to nothing at compare resolution, and it shrinks a golden from a ~6 MB noisy 16-spp full-res PNG to under half a megabyte, small enough to keep in git. `--update` stores the *already-downscaled* image, so in check mode the resize is a no-op on the golden side and the two paths agree by construction.

On failure the render is saved beside the golden as `<name>.actual.png` at **full** resolution — a human eyeballing drift wants the real pixels. That is also a footgun: ~6 MB next to a sub-500 KB golden, and `.gitignore` covers only `*.diff.png`.

drift = golden.replace(".png", ".actual.png")tests/golden/render_golden.py:238

Which shader the goldens actually gate

The manifest is ten scenes, all with the denoiser explicitly off: the harness pins raw deterministic beauty, treating denoised output as a separate, unpinned concern. Five run the example binaries. Two of those are path traced on the offline profile, two are the deferred hybrid on the same content (`cornell_box_deferred` and `damaged_helmet_deferred`), and one, `cornell_box_rt_realtime`, runs the realtime profile.

"command": "./build/cornell_box {out} 16 --denoise=none",tests/golden/manifest.json:49

The other five render the checked-in scene files in `assets/scenes/` through the `ohao` CLI, one per example scene, and compare against the *example's* golden rather than a copy of it — two goldens would let the file and the code drift apart unnoticed. Five PNGs back ten scenes.

"command": "./build/ohao run assets/scenes/cornell_box.scene.json --render {out} --mode rt_offline --spp 16 --denoise none",tests/golden/manifest.json:90

The RT profile that command selects is not obvious. With no mode flag the examples default to `RenderMode::RTOffline`, which instantiates `RTOfflineRenderer` — and that profile overrides the `PathTracerShaderSet` with the *offline reference* raygen, not the `pt_raygen.rgen` named in the shader-set member initializer.

"bin/shaders/rt_pt_raygen_offline.rgen.spv",ohao/render/rt/rt_profile_renderer.hpp:204

That covers more than one file. `RTRealtimeRenderer` names the same miss, closest-hit and any-hit SPIR-V modules as the offline profile and differs only in the raygen entry, so three of the realtime profile's four stages are under the offline goldens before `cornell_box_rt_realtime` adds the fourth.

"bin/shaders/rt_pt_raygen_realtime.rgen.spv",ohao/render/rt/rt_profile_renderer.hpp:189

So is the include graph the offline raygen compiles in: `pbr_unpack.glsl`, `mis.glsl`, `env_sampling.glsl`, `sampler_api.glsl`, `nrd_frontend.glsl` and `ggx_aniso.glsl`, plus what those pull in turn. Those six are the same six the realtime raygen includes.

#include "includes/rt/nrd_frontend.glsl"shaders/rt/pt_raygen_offline.rgen:55

The realtime scene was added after `rt_realtime` lost the device and wrote an all-black frame — bindings 29–35 were never written into the descriptor set — and it is looser than the offline pair (`max_abs_diff` 10, `max_diff_frac` 0.05), because `pt_raygen_realtime.rgen` reads neighbour pixels of images the same dispatch writes and is not bit-exact run to run. It also puts the PCG branch of `sampler_api.glsl` under the gate: the sampler is a specialization constant baked at pipeline creation, the offline profile bakes Sobol, and the realtime profile PCG. What has no golden is every denoised path.

"_note": "Realtime path tracer (ReSTIR GI reservoirs, temporal history, 19 frames). Added 2026-10-10 after it lost the device and wrote an all-black frame on master and on this branch: bindings 29-35 (reservoirs, spec hit-distance) were never written into the descriptor set. A black frame fails here twice -- the uniform-frame check and max_abs 225. Not bit-exact run-to-run: pt_raygen_realtime.rgen reads accumBuffer/normalAOV at neighbour pixels in the same dispatch that writes them, a race. Fresh-vs-fresh measured max_abs 3-5, diff_frac ~0.015 at compare res, hence 10 / 0.05."tests/golden/manifest.json:86

The deferred pair covers the other half. They render the G-buffer, the cascaded shadow pass, deferred lighting, the post chain and, where the device supports it, the RT shadows and GI, and they check the render-world migration against the previous renderer's own output: `cornell_box_deferred` was captured before that migration and `damaged_helmet_deferred` serves the same purpose on the helmet. The deferred helmet is looser than the rest, with its own tolerances, because its render is not bit-exact run to run.

The `16` is spp, not frames — `cornell_box` renders `samples + 3`, so the golden pins 19 accumulation frames. The deferred scenes pass `deferred` and a small sample count, and the count is ignored: the same line fixes a deferred run at ten frames.

const int frames = cli.useDeferred ? 10 : (samples + 3);examples/cornell_box.cpp:84

All ten scenes run on a fresh clone, which was not true for two months and is worth the paragraph.

The second scene used to invoke `model_viewer` on `assets/showcase_objects/MetalRoughSpheres.glb`. That file was in no clone and on no machine — not untracked, simply absent. What made it survive undetected is that `model_viewer` printed the Assimp error, carried on, rendered an **empty scene**, wrote a valid PNG and **exited 0**. The harness checks the exit code and whether the file exists; both passed. So the corpus spent two months comparing a picture of nothing against a golden full of geometry and reporting it as a large pixel difference — a missing asset wearing the costume of a rendering regression.

Three changes close it. `model_viewer` and `turntable` now return non-zero when a model fails to load, rather than rendering nothing successfully. The harness captures the child's stderr instead of discarding it, so the cause reaches the reader. And it rejects a frame with no spatial structure, on the principle that a uniformly coloured image is not a render of a scene.

<< "model_viewer renders nothing without a model; refusing to "examples/model_viewer.cpp:109
def degenerate(path):tests/golden/render_golden.py:101

The scene itself is now `damaged_helmet`, on `assets/test_models/DamagedHelmet.glb` — tracked, 3.7 MB, and the same kind of subject: a metal/rough glTF under an HDRI.

"command": "./build/model_viewer assets/test_models/DamagedHelmet.glb {out} 16 --denoise=none",tests/golden/manifest.json:57

Where the gate runs, and why not in CI

Enforcement is a committed pre-push hook, opt-in via `git config core.hooksPath .githooks`. It soft-skips when the engine has not been built, so a docs-only checkout is never blocked.

if [ ! -x build/cornell_box ]; then.githooks/pre-push:13
Why

The gate sits on the developer's machine because the harness needs a GPU with Vulkan ray tracing and hosted runners have none. The rejected alternative — a self-hosted GPU runner — buys enforcement nobody can skip, at the price of owning hardware. The only committed workflow builds the documentation site; the `ci.yml` (build + ctest + lint) described in the Phase 0 design does not exist, so this opt-in hook is the entire automated net.

What the unit tests pin

Three GoogleTest binaries live under `tests/renderer`. Each compiles the one or two `.cpp` files it needs into its own target instead of linking `ohao_renderer`, so they run with no Vulkan loader, no device and no GPU — which is what would make them CI-able, where the goldens are not, if a CI workflow existed.

add_executable(sobol_test sobol_test.cpptests/renderer/CMakeLists.txt:107

`sobol_test` pins the first eight points of dimensions 0–3, but only dims 0–1 are externally anchored — against Joe-Kuo `new-joe-kuo-6.21201`. The dim-2 expectations are, by the test's own comment, bit-expanded from the same `kDirectionNumbers` table the test is checking, so dims 2–3 pin the XOR-accumulate loop and say nothing about the table: a wrong direction number in those rows is invisible to this test.

// Dim 2 reference values, computed from the dim-2 direction numberstests/renderer/sobol_test.cpp:10

It then probes the one place a direct-bit-expansion generator breaks: at index $2^{31}$ the dimension-1 direction number is `0xFFFFFFFF`, which a naive `uint`→`float` cast rounds to exactly 1.0 and pushes out of $[0,1)$.

float v = SobolGenerator::sample1D(2147483648u, 1);tests/renderer/sobol_test.cpp:67

`SobolGenerator` and `owenScramble` have zero callers anywhere in the engine. The sampler that ships is the GLSL port in `shaders/includes/rt/sampler_sobol.glsl`; the C++ is a hand-maintained mirror kept as a testable oracle for it.

// this exactly; keeping the two implementations in lock-step lets the CPUohao/render/rt/owen_scramble.hpp:11

Nothing automated enforces that mirroring — they do currently agree, hash constants and 24-bit shift included. A divergence on the GLSL side would not fail `sobol_test` at all; it would surface as a golden failure, because the offline profile's settings select Sobol.

.samplerType = SamplerType::Sobol,ohao/render/rt/rt_settings.hpp:59

That field is what actually reaches the shader: the pipeline builder copies `m_renderSettings.samplerType` into a `VkSpecializationInfo` for constant id 0, which is the `SAMPLER_TYPE` the dispatch functions in `sampler_api.glsl` branch on.

uint32_t samplerTypeVal = static_cast<uint32_t>(m_renderSettings.samplerType);ohao/render/rt/path_tracer_pipeline.cpp:80

`env_cdf_test` asserts the invariants the GPU inverse-CDF lookup depends on: marginal and conditional rows monotone non-decreasing and terminating at 1.0, and a hot texel pulling over half the mass into its row and column. `denoise_parse_test` encodes a *removal* — with the OptiX backend deleted, `--denoise=optix` must degrade to OIDN rather than to `None`, so old command lines keep rendering denoised instead of silently returning noise.

TEST(DenoiseTypes, OptixRemovedFallsBackToOidn) {tests/renderer/denoise_parse_test.cpp:29

A fourth binary, `renderer_test`, initializes Vulkan, uploads a red quad, renders one RTOffline frame and writes a PNG — but never inspects a pixel, returning 0 even when `getPixels()` hands back null. An init-and-teardown canary, fine to have provided nobody reads its `ALL PASS` as a claim about the image.

std::cout << "=== ALL PASS ===" << std::endl;tests/renderer/renderer_test.cpp:71

Three more binaries in the same directory do inspect pixels, by comparing renders with each other rather than with a committed image, and each ends with a one-line JSON summary. The first two build a fresh renderer per render. `instantiate_gpu_test` renders the deferred Cornell box once from hand-spawned meshes and once from `MeshSource` entities through the instantiate system, and requires the two to be bit-identical. `scene_view_gpu_test` renders the Cornell box and `model_viewer`'s helmet room three ways — camera and environment set by hand, applied from the world's `Camera` and `Environment` entities, and after a round trip through scene text — and requires them to match: exactly for deferred, within the RT path's rare 1-LSB flips for the helmet. `restore_render_gpu_test` drives the CLI's own session and render host on the checked-in Cornell scene with one renderer per sequence: a capture, a move that must change the image, a `world.restore` after which the capture must equal the first — bit-identical with post effects off, within 1 LSB with TAA, SSAO and bloom on. Validation is on for every deferred run and must report nothing.

{"cornell: the Camera entity renders exactly as the hand-set camera", c12.bytes == 0},tests/renderer/scene_view_gpu_test.cpp:195

`engine_tests` runs nine sections. Two are the ones its header comment numbers first — `EventBus` and `CommandHistory` — and a third, `Assets`, checks the loader's extension list; scene entities are covered by `ecs_tests`. The fourth, `runMetaTests`, is the only place the renderer's compile-time contracts are exercised at all: fourteen cases covering RT profile traits (offline four bounces, realtime two), `DenoiseModeTraits` against their runtime mirrors, `RTFeatureFlags` and `makeFeatureSettings`, `applyDenoisePolicy` and the jitter / fresh-sample / AOV-accumulation predicates, `as_span` and `span_covers_image`, `Result` and `VoidResult`, render-graph handles with culling AABBs and the camera, physics handles with `ShapeInfo`, and a rigid body that exists and carries a name with no scene component behind it.

void runMetaTests() {tests/engine/engine_tests.cpp:370

Four more stand up real Vulkan with no swapchain: the deferred pipeline, the path tracer on an RT-capable device, a headless frame recorded, submitted and read back, and the renderer's resize and refusal paths — two of those resize cases with the validation layer on, failing on what the layer reports. Each reports itself skipped, not passed, when the machine has no device or no layer.

static void runHeadlessDeferredRenderTests() {tests/engine/engine_tests.cpp:1090

The ninth section drives the persistent render world on a real device:

static void runRenderSceneTests() {tests/engine/engine_tests.cpp:1461

twelve cases covering mesh registration with its AABB, table entry and BLAS; static instances uploading once while moving ones upload in proportion; missing material references falling back to the default; instance-table and mesh-arena growth without destroying a buffer a frame still reads; the raster shadow-caster rule; a material edit reaching the packed table row; the 1×1 tint textures being shared per encoded colour; the path tracer tracing the render world; texture slots past 1024 reaching the tracer; a moved instance refitting the TLAS; and a slot released and reused in one frame forcing a rebuild.

Its `EXPECT` macro `return`s from the enclosing section function, so the first failure silently skips the rest of that section; the exit code is still non-zero, but the pass count understates how much was never attempted.

do { if (!(expr)) { TEST_FAIL(msg); return; } } while(0)tests/engine/engine_tests.cpp:79

The "GPU layout contracts" case is five assertions and they are not all the same kind. Three are `static_assert`s that can only fail the build, and only one of those — `sizeof(GPULight) == layout::kGPULightBytes` — restates an `OHAO_ASSERT_GPU_LAYOUT` in the owning header; the two `MaterialGpuPack` lines restate plain `static_assert`s in `layout_meta.hpp`. The remaining two go through `EXPECT`, so a `MaterialGpuPack::vec4Count` or `GpuPod<GPULight>` regression is a failing *run*, not a failing build.

EXPECT(layout::MaterialGpuPack::vec4Count(2) == 6, "2 materials = 6 vec4s");tests/engine/engine_tests.cpp:421

Three more binaries build by default and never touch an image: `physics_backend_tests` (59 cases over Jolt body lifecycle, CCD, the 16-layer collision system, queries, contact callbacks, constraints and the character controller), `force_generator_tests` (54 cases over force volumes, wind, buoyancy, Hooke's-law springs, the force registry and AABB math) and `audio_system_tests` (13 cases over the miniaudio wrapper's volume and handle state). They share `engine_tests`' hand-rolled `TEST_BEGIN`/`TEST_PASS` harness rather than GoogleTest, and each is a plain `main` returning non-zero on failure.

Two more binaries cover the entity layer and the windowed host. `ecs_tests` (26 cases) checks transform propagation and hierarchy rules — parenting, cyclic `setParent` rejection, subtree destruction, system order — and, on a headless renderer that it skips when no device exists, the render extract: slot creation and release, lights following transforms in creation order, a model's materials becoming submeshes, an emissive texture yielding a proxy light, and unknown mesh handles being skipped. `runtime_tests` (21 cases) needs no GPU: it pins the fixed-step clock, the input action map and the swapchain-selection helpers.

option(BUILD_PHYSICS_TESTS "Build physics backend tests" ON)CMakeLists.txt:116

The scene-file layer has its own CPU-only suites, each a plain `main` that ends with a one-line JSON summary. `reflect_tests` covers the type registry, schema export, the JSON writer and reader, float formatting, and the rule that the ECS system sources may not include `reflect/` or `api/`. `scene_tests` covers the engine's component registrations, entity ids, the scene codec with its error corpus and migration, snapshots, and instantiate against a fake backend. `api_tests` covers the agent API's methods, commands and their inverses, queries and summaries; `systems_tests` the engine-provided spin system.

option(BUILD_API_TESTS "Build API tests (methods, commands, inverses, queries; CPU only)" ON)CMakeLists.txt:173

Two Python harnesses sit beside them. `tests/cli/check_cli.py` runs each case in `tests/cli/cases.json` twice from a fresh scratch directory, requiring the same bytes both times and, where a case says so, stdout and written files equal to checked-in expectations; `--cpu-only` skips the cases that create a device. Its last two cases are what keep the checked-in scenes honest: each example's `--save-scene` output must equal its file under `assets/scenes/` byte for byte, so editing a builder without regenerating the file fails here.

"files": {"build/cli_tmp/cornell_box.scene.json": "assets/scenes/cornell_box.scene.json"}},tests/cli/cases.json:107

`tests/reflect/check_scene_schema.py` runs the generated JSON Schemas through a stock validator and needs the `jsonschema` package.

What only looks wired up

Four things under `tests/` look like tests and are not.

  • `enable_testing()` is called nowhere in the repository, so CMake emits no

`CTestTestfile.cmake` and `ctest -N` reports zero tests. Every `add_test` and `gtest_discover_tests` call under `tests/` is inert; each suite runs by executing its binary.

  • `tests/CMakeLists.txt` is orphaned — the root adds `tests/renderer`,

`tests/engine` and the rest individually, never `tests` itself. Fortunate: that file declares a second `engine_tests` target and re-adds `tests/renderer`, so wiring it in would fail configuration outright.

gtest_discover_tests(engine_tests)tests/CMakeLists.txt:16
  • `tests/renderer/renderer_pipeline_tests.cpp`, 939 lines advertising "Phase 1–5"

coverage of the deferred pipeline, is in no `CMakeLists.txt` and could not compile if it were: five of its eighteen project includes name headers no longer in the tree — `volumetric_pass.hpp`, `motion_blur_pass.hpp`, `dof_pass.hpp`, `ssgi_pass.hpp`, `indirect_draw_buffer.hpp`. The other thirteen resolve.

#include "render/deferred/ssgi_pass.hpp"tests/renderer/renderer_pipeline_tests.cpp:32
  • `tests/shadow_system/` is the same defect one step further along: the root

`CMakeLists.txt` declares its option `OFF` with the reason written inline — it references `unified_light.hpp`, `shader_bindings.hpp` and `ohao_vk_descriptor_builder.hpp`, none of which exist under `ohao/`. It at least fails honestly, by never being configured.

# Shadow system tests — OFF until renderer/lighting/ headers are implementedCMakeLists.txt:136

Beside that, `tests/reference_scenes/` is a human-reviewed library — one scene so far — logging each feature checked against a committed reference render. Nothing scripts it; it is a review artifact, not a gate.

Key idea

The whole automated image-quality net is five 640×360 PNGs backing ten scenes, compared under two tolerances, by a hook a developer must opt into, on a machine with a GPU. Every scene loads only tracked assets, so on a fresh clone all ten run — but only where the hook is installed and the engine built. Judge this suite by what executes, not by what is checked in.

Contracts

  • Re-enabling temporal reprojection in `pt_raygen_offline.rgen` does not merely change the goldens, it makes them unreproducible: the race has no defined ordering, so `--selftest` starts failing against itself.
  • The harness must run from the repository root — manifest commands and golden paths are repo-relative. The executable is resolved through the per-configuration subdirectories and the `.exe` suffix, so `./build/cornell_box` finds `build/Release/cornell_box.exe`; one that is genuinely absent is reported as a scene FAIL (`could not launch …`), not a traceback. The pre-push hook sidesteps the working-directory requirement by `cd`-ing to the toplevel first.
  • Goldens must come from `--update`, which stores the downscaled image. One regenerated at full resolution is a shape mismatch, reported cleanly as `size mismatch vs golden` in check mode. `--selftest` never opens the golden at all — it renders twice and diffs actual against actual — but it dereferences its stats dict unguarded, so if the two renders of one command ever disagree in shape it raises instead of reporting.
  • Adding a manifest scene is the only way a fixed bug becomes non-regressible; nothing else in the tree pins an image against a committed reference — the `*_gpu_test`s only compare fresh renders with each other.
