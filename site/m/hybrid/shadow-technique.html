The one term the GBuffer cannot hold

A deferred GBuffer stores everything the lighting equation needs at a point — position, normal, albedo, roughness, metallic — except the one quantity that is not a property of the point at all. Visibility depends on the whole scene along a ray. Cascade shadow maps answer it by re-rasterising depth from the light, at a pass per cascade and the cost of projective aliasing, cascade seams and a bias nobody gets right. `RTShadowTechnique` asks the TLAS instead: no light-space projection, no cascade split, no depth-map resolution to alias against. It has a bias of its own and it cannot see an alpha mask — both below.

The result is a screen-resolution `R32G32_UINT` image holding eight 8-bit visibility channels, one per shadow light (x: lights 0-3, y: lights 4-7, lowest byte first), 0 = shadowed, 255 = lit:

constexpr VkFormat kVisFormat = VK_FORMAT_R32G32_UINT; // eight 8-bit visibility channelsohao/render/rt/rt_shadow_technique.cpp:59

The deferred lighting fragment shader reads it once, at binding 14, before its light loop — an integer `texelFetch` at the fragment's own pixel, since the image is the lighting pass's size:

const uvec2 rtShadow = rtShadows ? texelFetch(rtShadowVisibility, ivec2(gl_FragCoord.xy), 0).xy : uvec2(0u);shaders/core/deferred_lighting.frag:248

Inside the loop each light picks its own byte by the slot stored in its `params.w`, and the BRDF result is multiplied by it over 255.

shadow = float((word >> (8u * uint(slot & 3))) & 255u) * (1.0 / 255.0);shaders/core/deferred_lighting.frag:281

Binding the view is also what switches the pipeline. `setRTShadowMask` only stores it; `execute` zeroes the whole flag word and rebuilds it from the bound views every frame, before pushing it.

m_params.flags = 0;ohao/render/deferred/deferred_lighting_pass.cpp:173

In that rebuild the RT bit and the CSM bit are the two arms of a single if/else keyed on whether an RT visibility view is bound at all, so the two shadow systems are mutually exclusive by construction rather than by convention.

else if (m_shadowMapView != VK_NULL_HANDLE)ohao/render/deferred/deferred_lighting_pass.cpp:182

The fragment shader repeats the structure, branching on bit 5 first and reaching CSM only through the `else`.

} else if ((pc.flags & 4u) != 0u && lightType == 0) {shaders/core/deferred_lighting.frag:282

The renderer goes one step further and does not draw the cascades at all in a frame that traces: whether RT shadows run is decided before the graph is built, and the `csm` pass is added only when they do not.

if (m_csmPass && !rtShadows) {ohao/render/deferred/deferred_renderer.cpp:291

Which lights get a channel

The light table decides. Walking the raster lights in light order, it gives each light whose `castShadows` is set the next channel and records it in `params.w`:

shadowSlot = static_cast<float>(m_shadowLights.size());ohao/render/scene/light_table.cpp:149

There are eight channels and the raster light table holds up to 65,536 lights, so only the first eight casters get one:

inline constexpr uint32_t kMaxShadowLights = 8;ohao/render/scene/render_scene_types.hpp:101

A caster past the eighth keeps `kShadowNever` and renders unshadowed. The table counts those, and `RenderScene::shadowCastersWithoutChannel()` reports the count; test 8 checks that Cornell's twelve casting lights give eight channels and four unshadowed lights.

++m_shadowCastersWithoutChannel;ohao/render/scene/light_table.cpp:152

A light with `castShadows` off gets `kShadowNever` (-1), and so does every emissive proxy, which sits inside its own mesh.

light.params = glm::vec4(0.0f, 0.0f, -1.0f, kShadowNever); // inside its own mesh: never shadowedohao/render/scene/light_table.cpp:177

The lighting shader reads the two cases directly. A negative slot is never occluded; any other slot takes its channel when the RT bit is set, and without it a directional light gets CSM.

int slot = int(round(light.params.w));shaders/core/deferred_lighting.frag:277

The lights with a channel, in channel order, are `RenderScene::shadowLights()`, which the dispatch hands to the deferred renderer each frame (or, for a scene with no lights at all, the fallback sun as channel 0). RT shadows run only when that list is non-empty, the device has ray queries and the scene has a TLAS: a frame in which no light casts shadows traces nothing.

const bool rtShadows = m_useRTShadows && m_rtShadow && sceneTlas != VK_NULL_HANDLE && m_gbufferPass &&ohao/render/deferred/deferred_renderer.cpp:287

Two compute passes, no ray tracing pipeline

The technique is two compute passes, timed under their registry names: the trace, `rt.shadows`, and in realtime quality the filter, `rt.shadows.filter`. Neither is a ray tracing pipeline. The trace uses inline ray queries — no shader binding table, no raygen, miss or hit shaders — because a shadow ray needs no hit shader: it asks one yes/no question. Without `VK_KHR_ray_query` `init()` fails and CSM shadows the frame.

// Both passes are compute: the trace uses inline ray queries (VK_KHR_ray_query; without itohao/render/rt/rt_shadow_technique.hpp:5

Both are Slang, one entry point each (`trace` in `rt/shadow_trace.slang`, `filter` in `rt/shadow_filter.slang`), loaded by name into plain compute pipelines through the helper RT shadows and RT GI share in `rt_compute.cpp`:

return rtc::createComputePipeline(m_device, "rt_shadow_trace.slang.spv", "trace", m_traceSetLayout,ohao/render/rt/rt_shadow_technique.cpp:198
ci.stage.pName = entry;ohao/render/rt/rt_compute.cpp:128

The query treats every intersection as opaque and stops at the first one it accepts; the answer is whether anything was committed.

RayQuery<RAY_FLAG_ACCEPT_FIRST_HIT_AND_END_SEARCH | RAY_FLAG_FORCE_OPAQUE | RAY_FLAG_SKIP_CLOSEST_HIT_SHADER> q;shaders/rt/shadow_trace.slang:153
return q.CommittedStatus() == COMMITTED_NOTHING ? 1.0 : 0.0;shaders/rt/shadow_trace.slang:156
Why

The rejected alternative is a closest-hit query reporting hit distance — the channel an NRD-style denoiser wants for sizing its spatial filter. Accepting the first hit gives it up: traversal stops at any intersection rather than proving the nearest one. The filter makes up for it with guides it does have, the pixel's distance from the camera and its normal; what it cannot do is widen the kernel where the occluder is far, so penumbra width comes from the light's sampled area, not from the filter.

The lights reach the trace in a storage buffer, not push constants: each frame slot owns a host-visible buffer holding up to eight `ShadowLight`s (the struct comes from the shared layout) and, behind them, a counter. It is an `rtc::HostBuffer`, device-local memory when the device has a host-visible kind of it (resizable BAR), because every pixel reads every light; RT GI's light buffers are made the same way.

ai.memoryTypeIndex = findMemoryType(physicalDevice, req.memoryTypeBits, host | VK_MEMORY_PROPERTY_DEVICE_LOCAL_BIT);ohao/render/rt/rt_compute.cpp:153

Four lights a pixel, by importance

In realtime quality a pixel does not trace every light. It ranks the frame's shadow-casting lights by what each is worth to it — intensity over squared distance, a directional light its plain intensity:

return intensity / max(d2, 1e-4);shaders/rt/shadow_trace.slang:103

A light is worth 0 where it cannot contribute: a point or spot light beyond its range plus its radius, or one whose whole sphere lies behind the surface. A rectangle is pushed with a range of 0, which the test reads as unlimited. The importance has no cone term, so a spot light competes for a pixel outside its cone as if it were a point light.

if (type == 1u && range > radius && d2 > range * range) return 0.0;shaders/rt/shadow_trace.slang:93

The ranking is a sort key: the importance's float bits with the light index in the low bits, so ties go to the lower index, and bit 3 is set so a key is never 0 for a light worth anything.

key[l] = imp > 0.0 ? (asuint(imp) & ~15u) | 8u | (7u - l) : 0u; // bit 3 set: never 0 when imp > 0shaders/rt/shadow_trace.slang:227

The pixel finds the budget-th largest key and traces one ray to a sampled point on each light at or above it. The budget is `ShadowInput::maxLightsPerPixel`, clamped to `kShadowLightsPerPixel`, four:

std::min(input.maxLightsPerPixel, shared::kShadowLightsPerPixel));ohao/render/rt/rt_shadow_technique.cpp:306

A pixel with more lights worth tracing than it may trace adds one to the counter:

if (wanted > budget) InterlockedAdd(dropped[0], 1u);shaders/rt/shadow_trace.slang:231

The counter is read on the CPU only after that slot's fence has signalled, never by waiting, and the newest finished frame's count is what `render.stats` reports as `shadowLightsDropped`:

if (!m_latestDropped || s.frame >= m_latestDropped->frame) m_latestDropped = Dropped{s.frame, pixels};ohao/render/rt/rt_shadow_technique.cpp:212
st->shadowLightsDropped = dropped->pixels;ohao/runtime/frame_capture.cpp:262

The trace writes no visibility in realtime. It writes a packed `meta` texel per pixel: in x, the filter's guide — the distance from the camera as a bfloat16 (a float's top 16 bits) and the octahedral normal at 8 + 8 bits; in y, a traced bit and a visible bit per light and a surface bit.

meta[pixel] = uint2(dist | (oct.x << 16u) | (oct.y << 24u), traced | (visible << 8u) | (1u << 16u));shaders/rt/shadow_trace.slang:260

What the estimator actually computes

Direct lighting from an area source is

$$ L_o(x,\omega_o) = \int_{\Omega_\ell} f_r(x,\omega_o,\omega)\, L_i(\omega)\, V(x,\omega)\, (\mathbf{n}\!\cdot\!\omega)\, d\omega $$

where $\Omega_\ell$ is the solid angle the light subtends at the shading point $x$, $f_r$ is the BRDF, $L_i$ the incident radiance, $\mathbf{n}$ the shading normal, and $V \in \{0,1\}$ the binary visibility along $\omega$. One channel per light cannot represent that integral. What the technique evaluates is the separable approximation

$$ L_o \approx \bar V(x)\; f_r(x,\omega_o,\bar\omega)\, L_i(\bar\omega)\,(\mathbf{n}\!\cdot\!\bar\omega), \qquad \bar V(x)=\frac{1}{N}\sum_{s=1}^{N} V(x,\omega_s) $$

where $\bar\omega$ is the direction the lighting pass uses for the light. In reference quality $\bar V$ is exactly that mean: eight rays a light a frame, averaged, then folded into a running mean over the reference frames since the last temporal reset, so $N$ grows by eight every frame. $k$ is the technique's count of the frames already in the mean (`history.x`), which a reset, new images or any realtime frame zero, so the mean never blends into a stale or undefined image.

const float4 meanLo = prevLo + (lo - prevLo) / (k + 1.0);shaders/rt/shadow_trace.slang:209

In realtime each pixel contributes one binary sample a light a frame, and $\bar V$ is a weighted mean over neighbouring pixels and past frames instead (the filter, below). Either way the lighting pass multiplies that single number by a BRDF evaluated only at $\bar\omega$. Factoring $V$ out is exact wherever it is constant across the light — everywhere but the penumbra; inside one, the error is the covariance between visibility and the cosine-weighted BRDF over the source, the term a path tracer keeps and this one discards.

The filter

The filter turns one ray a light a pixel into the eight channels lighting reads. It runs in 16×16 workgroups, and each group first decodes a 20×20 tile of `meta` — its pixels plus a two-pixel apron — into shared memory, so every 5×5 neighbourhood is read from there:

groupshared uint gBits[kSide * kSide]; // traced (bits 0-7) and visible (bits 8-15) per light; 0 for skyshaders/rt/shadow_filter.slang:30

Most pixels never run the weighted kernel. Over the 5×5, a light every neighbour that traced it saw lit is lit, and one every such neighbour saw occluded is occluded, whatever the weights; only a light seen both ways — a penumbra, or noise — is "mixed":

const uint mixed = anyLit & anyHidden;shaders/rt/shadow_filter.slang:112

A pixel traces at most four lights, so at most four are mixed, and one `float4` accumulates them. A neighbour's weight falls with its ring (1, 0.6, 0.3), with its depth difference relative to 5 % of the centre's distance, and with the fourth power of the normals' cosine; neighbours that did not trace the light, and sky, do not count.

float w = ring == 0 ? 1.0 : ring == 1 ? 0.6 : 0.3;shaders/rt/shadow_filter.slang:143
const float invTol = 1.0 / (0.05 * gc.w + 1e-3);shaders/rt/shadow_filter.slang:132

Then the temporal step. The pixel is reprojected by the G-buffer's velocity to the nearest texel of last frame, and last frame's output is blended in only where that texel is a surface, within 10 % of this pixel's distance, with normals within $\cos^{-1} 0.9$, and only for lights both pixels traced:

if (isSurface(pm) && abs(gp.w - gc.w) < 0.1 * gc.w && dot(gp.xyz, gc.xyz) > 0.9)shaders/rt/shadow_filter.slang:183

The blend weight is $1/(n+1)$ for $n$ frames of history, floored at $1/16$ (`kShadowHistoryFrames`): a still camera after a reset averages its frames evenly, then settles into a moving average.

const float alpha = 1.0 / float(min(pc.extent.w + 1u, kShadowHistoryFrames));shaders/rt/shadow_filter.slang:185
m_historyFrames = m_historyValid ? m_historyFrames + 1 : 1;ohao/render/rt/rt_shadow_technique.cpp:367

The output is quantised to 8 bits with a hash dither in place of rounding, so the quantisation error averages out over frames instead of biasing the history; 0 and 1 stay exact.

const uint4 q = uint4(min(saturate(v) * 255.0 + dither, 255.0));shaders/rt/shadow_filter.slang:56

The output is also next frame's history, so the meta and visibility images are ping-pong pairs, this frame writing one half while reading the other. History is dropped on the first frame after a temporal reset, on a resize, and by any frame rendered in reference quality.

if (m_frameIndex == 0) m_historyValid = false;ohao/render/rt/rt_shadow_technique.cpp:330

Reference quality

`RenderQuality::Reference` is the converged answer the realtime frame approximates. The same trace pass runs with no per-pixel cap and no filter: every light, `kShadowReferenceRays` (eight) rays each, every frame.

reference ? shared::kShadowReferenceRays : 1u);ohao/render/rt/rt_shadow_technique.cpp:308
v /= float(kShadowReferenceRays);shaders/rt/shadow_trace.slang:206

The running mean lives in two `RGBA32F` images (lights 0-3 and 4-7), created on first use; in realtime a 1×1 stand-in is bound in their place. The trace writes the mean, packed to 8 bits a light with round-to-nearest, straight to the visibility image, and the renderer adds no filter pass:

m_renderGraph.addComputePass("rt.shadows.filter",ohao/render/deferred/deferred_renderer.cpp:405

Three penumbra samplers

Softness comes from jittering the sample target, and the trace has a geometry per light type. A directional light (type 0) gets a tangent basis around the light direction and an offset inside a disk of the light's angular radius, with $\sqrt{r_1}$ making samples uniform in disk area — a small-angle construction, since the offset is the angle rather than its tangent:

const float angle = light.edge1AndRadius.w * sqrt(r1);shaders/rt/shadow_trace.slang:121

A point or spot light (type 1) instead targets a uniformly distributed point on a sphere of the light's radius:

const float z = 1.0 - 2.0 * r2;shaders/rt/shadow_trace.slang:136

A rectangle (type 2) is sampled uniformly over its area, from the corner its position names along its two edges — the convention the path tracer samples it by:

target = light.positionAndType.xyz + light.edge1AndRadius.xyz * r1 + light.edge2AndRange.xyz * r2;shaders/rt/shadow_trace.slang:131

Because $z = 1 - 2r_2$ is uniform on $[-1,1]$, the sphere branch is a correct uniform-area sampler of the sphere *surface* — with a consequence worth naming. By Archimedes' hat-box theorem a uniform distribution on a sphere projects to a uniform distribution on any single axis, so an occluder edge sweeping across the source yields a **linear** visibility ramp, not the circular-segment S-curve a genuinely disk-shaped source produces. The difference shows at the two ends of the penumbra, where the true profile approaches full light and full shadow tangentially and the linear one arrives with a crease. Reference quality converges to that ramp; realtime approaches it only as far as its spatial and temporal means reach.

Rays and seeds

Realtime cost scales with the lights a pixel traces: one ray each, at most four a pixel, whatever the light count. Reference costs eight rays per light per pixel per frame. The push constants carry the extent, the light count and the budget, then the seeds, the quality and the rays per light:

pc.extent = u4(input.width, input.height, m_lightCount,ohao/render/rt/rt_shadow_technique.cpp:305

Measured on `cornell_720p` (1280×720, RTX 5070 Laptop, 2026-10-24), with eight shadowed lights and four traced a pixel: `rt.shadows` 0.252 ms and `rt.shadows.filter` 0.061 ms, within budgets of 0.30 and 0.08 — moved there from SSR, the G-buffer and sky + particles by Frank's ruling of 2026-10-25, the frame's 1.50 ms unchanged, after the original 0.20 and 0.05 proved out of reach with four rays a pixel. On `helmet_game_720p`, four lights: 0.092 ms and 0.045 ms.

Every random number is an integer PCG hash of the render seed, the frame index since the last temporal reset and the pixel, hashed once per pixel, then of the light, the ray and the dimension:

const uint h = pcg(pixelKey ^ pcg((light << 24u) ^ (s << 4u) ^ dim));shaders/rt/shadow_trace.slang:60

The deferred renderer supplies both seeds, the one `setRenderSeed` stored and the counter `resetTemporalState` zeroes, so the noise decorrelates from frame to frame — which is what lets the filter's temporal mean converge — while two renders of the same world with the same seed trace the same rays. The filter's dither hashes the same seeds.

Sharp edges

The ray origin is pushed a flat 0.05 world units along the shading normal, with `TMin` = 0.001 behind that:

const float3 origin = p + n * 0.05;shaders/rt/shadow_trace.slang:186

The offset is absolute, not scaled by depth or texel footprint: too large for centimetre-scale detail, where contact shadows detach into the ray-traced form of peter-panning, and too small for a kilometre-scale scene.

Sky pixels are detected by testing all four channels of the GBuffer position for exact zero:

if (all(position == float4(0.0))) // sky: nothing to shadowshaders/rt/shadow_trace.slang:169

The fourth is not a coverage bit — GBuffer0 packs metallic there:

outGBuffer0 = vec4(fragWorldPos, metallic);shaders/core/gbuffer.frag:148

The test works only because that attachment clears to (0,0,0,0); a non-metallic surface passing exactly through the world origin is classified as sky and comes out fully lit in every channel.

A light a pixel did not trace — worth nothing there, or past the per-pixel cap — is lit in that pixel's output. For the first that is free: the light contributes nothing, so there is nothing to occlude. For the second it is the cost the cap buys, and the dropped count is how big it is.

Samples whose jittered direction falls below the horizon count as zero visibility:

if (dot(n, dir) <= 0.0) return 0.0; // a surface facing away from the sample gets nothing from itshaders/rt/shadow_trace.slang:145

Inside the integral that would cost nothing — those directions carry zero cosine weight anyway. But a skipped sample still counts as a sample, so what reaches the channel is a binary horizon *indicator* averaged over the jitter, and the lighting pass multiplies it into a BRDF that already applies exactly one $\mathbf{n}\cdot\bar\omega$, at the unjittered direction.

return (diffuse + specular) * lightColor * NdotL;shaders/includes/brdf/brdf_ggx.glsl:169

The product is indicator × cosine: a step-shaped second falloff riding on the cosine, darkening a band near the terminator by an amount no BRDF term accounts for.

Finally the ray mask. The trace queries with `0x01`, named for static geometry only. The `RenderScene` builds every live, visible TLAS instance with mask `0xFF`, and a hidden or released slot with zero:

static const uint kRayMaskStatic = 0x01u; // RT_RAY_MASK_STATIC (render/rt/rt_visibility.hpp)shaders/rt/shadow_trace.slang:34
vi.mask = visible ? 0xFFu : 0u;ohao/render/scene/render_scene.cpp:112

so the filter passes every visible instance and rejects exactly the ones that should cast nothing. It is a visibility switch, not a static-versus-dynamic distinction: the companion `MASK_ANIMATED = 0x00` in `rt_visibility.hpp` has no users at all, since skeletal geometry left the RT path.

Key idea

Each channel is a boolean visibility average, not a shadow with radiance in it. Everything the technique gets right — hardness, contact, penumbra width — is decided by where the sample targets are placed; everything it gets wrong, at the terminator and inside the penumbra, follows from that scalar being pulled out of an integral it does not commute with. In realtime a fifth light that matters to a pixel is not dimmed but dropped: lit, and counted.

Contracts

  • `DeferredRenderer::onResize` forwards the new extent to `m_rtShadow` as well as `m_rtGI`. `resize` recreates both ping-pong pairs at the new extent and drops the history; the reference means come back on first use. The trace dispatches at `ShadowInput`'s extent, the filter at the technique's own, so the two must agree.
  • Each pipeline's descriptor set is written at record time into the set for the caller's `frameSlot`, one of `MAX_FRAMES_IN_FLIGHT`, and the slot's light buffer and counter are rewritten in `render()`. Both hold only while the caller passes the frame-ring slot whose fence it has just waited on; the counter is read only for slots whose fence the caller reports signalled.
  • The barrier before the trace discards this frame's meta and visibility halves (`oldLayout = VK_IMAGE_LAYOUT_UNDEFINED`) — every pixel is written each dispatch — and waits on fragment and compute reads of them from an earlier frame.
  • Light *i* of `ShadowInput::lights` is traced into channel *i*, and the lighting shader reads channel `params.w`. The two agree only because both come from one walk of the light table: `shadowLights()` lists the lights in the order their slots were handed out. A caller that builds its own list must keep that order; lights past `kShadowMaxLights` are ignored.
  • Realtime needs the G-buffer velocity view: `render()` returns without tracing when it is null, and then nothing is handed to lighting.
  • `setRTShadowMask` must run after the per-frame reset and before the lighting pass records, and only when `rendered()` is true — from the filter pass's callback in realtime, from the trace pass's in reference, both of which the graph records before `lighting`. The setter only stores the view; the flag bit the fragment shader branches on and the descriptor at binding 14 are both derived from it when the lighting pass records. Hand it over later and that frame records with bit 5 clear and the stand-in view bound.
