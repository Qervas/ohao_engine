One id resolves a material, and nothing is walked

A path-traced hit resolves its material through four lookups and no per-scene walk. The TLAS instance carries the render-world instance slot as its custom index. The closest-hit shader uses that slot to find the instance, the instance to find the mesh, and `gl_PrimitiveID` to find the triangle's submesh slot in the mesh's per-triangle stream. The slot is then resolved through the instance's material-reference list to a row of the material table:

uint slot = triSlot[mesh.triangleSlotOffset + uint(gl_PrimitiveID)];shaders/rt/pt_closesthit.rchit:122
uint matID = OHAO_MATERIAL_INDEX(inst, slot, materialRefs);shaders/rt/pt_closesthit.rchit:123

The resolution is a macro shared by the raster and RT shaders, and it is total: a slot past the instance's reference list falls back to material 0, the default.

((slot) < (inst).materialRefCount ? (refs)[(inst).materialRefOffset + (slot)] : 0u)shaders/includes/scene/scene_data.glsl:18

Nothing here depends on iteration order. Every table is keyed by an identity the instance carries — slot, mesh index, material index — instead of by position in a list that several loops must walk identically, so there is no visibility predicate to keep in step across files. The cost is moved to the edges, where the identities are assigned. A reference that names a material the table does not hold is clamped to 0 on the host when the instance is written, so the shader never indexes past the table:

refs[i] = (h.valid() && h.index < materialCount) ? h.index : 0u;ohao/render/scene/instance_table.cpp:102

and the custom index has only 24 bits, which is the ceiling on live instance slots:

vi.instanceCustomIndex = slot & 0xFFFFFFu; // 24 bitsohao/render/scene/render_scene.cpp:151

One BLAS per mesh, built at registration

Each mesh gets exactly one bottom-level structure, built when the mesh is registered, against the shared vertex and index arenas. The geometry is a single triangle list over the mesh's slice, so submeshes do not become separate geometries: the per-material information rides in the triangle-slot stream, indexed by primitive id, rather than in geometry indices. A build that cannot happen — no ray tracing, or fewer than three indices — leaves the mesh without a BLAS:

if (!m_ctx.rt || !m_ctx.rt->isSupported() || mesh.indexCount < 3) return;ohao/render/scene/mesh_registry.cpp:127

The instance that references such a mesh is still created and still rasterises; in the TLAS its acceleration-structure reference is zero, which Vulkan defines as an inactive instance:

// A reference of 0 makes the instance inactive (no BLAS: failed build). Aohao/render/scene/render_scene.cpp:152

A registered mesh's BLAS is built for fast trace and cannot be updated, so it never references its inputs after the build and survives the arenas being replaced by larger ones.

// A built BLAS (FAST_TRACE, no ALLOW_UPDATE) does not reference its inputs, soohao/render/scene/mesh_registry.cpp:388
: VK_BUILD_ACCELERATION_STRUCTURE_PREFER_FAST_TRACE_BIT_KHR;ohao/render/rt/rt_acceleration_structure.cpp:256

The one exception is a skinned instance's own mesh: its BLAS is built updatable (`ALLOW_UPDATE | PREFER_FAST_BUILD`) and refit in the `rt.blas.refit` pass whenever its pose changes, from the arenas' current addresses, and rebuilt every `kBlasRefitsPerRebuild` refits so a refit tree's quality does not drift:

buildInfo.flags = updatable ? VK_BUILD_ACCELERATION_STRUCTURE_ALLOW_UPDATE_BIT_KHR |ohao/render/rt/rt_acceleration_structure.cpp:254

The structures belong to the `RenderScene`. It owns its own `RTAccelerationStructure` and decides itself whether ray tracing is available; the renderer asks it.

A TLAS that is built or refitted inside the frame

The TLAS is not rebuilt per frame; it is built, refitted or left alone, decided from what changed. Each instance slot has a 64-byte `VkAccelerationStructureInstanceKHR` kept in a host mirror and a device-local buffer, and an edit to the slot recomputes its mirror entry. A change that alters the instance's *mask* — visibility — or its BLAS reference, or that creates or destroys the slot, is structural. A change to the transform alone is not.

if (structural || cur.mask != vi.mask || cur.flags != vi.flags ||ohao/render/scene/render_scene.cpp:188

The recording step reads that flag: a structural change, or no TLAS yet, builds; a transform-only change refits in `UPDATE` mode; nothing changed, nothing recorded.

const bool build = tlasStructural || rtAccel->getTLAS() == VK_NULL_HANDLE;ohao/render/scene/render_scene.cpp:241

Destroying an instance does not remove its slot from the TLAS. The slot's flags are zeroed so the GPU copy reads as invisible, and the instance's mask becomes 0 — it stays in the structure and no ray can hit it until a new instance reuses the slot:

m_gpu[slot].flags = 0; // the GPU copy reads as invisible until the slot is reusedohao/render/scene/instance_table.cpp:145

Slots are reused lowest-first, and a reused slot never refits — creation is always structural — because the custom index and mesh binding changed under the old structure.

If the allocation for a build fails, the dirty entries have already been uploaded, so the failure marks the next build structural rather than keeping the instance data dirty:

tlasStructural = true; // full build next frame covers this frame's changesohao/render/scene/render_scene.cpp:250

The TLAS storage is replaced when the instance count outgrows it, so the handle a pass read last frame can differ from this one. The dispatcher therefore binds the scene buffers to the path tracer only after `recordUpdates` has run:

// After recordUpdates: table growth and TLAS (re)creation replace handles.ohao/gpu/vulkan/render_dispatch.cpp:356

and the replaced storage goes to the retire queue and is destroyed only after `MAX_FRAMES_IN_FLIGHT` frames, because earlier frames may still be tracing against it. The barrier after the build names the stages that read the structure; compute and fragment stages are included only when the device enabled ray query, since naming a stage whose extension was not enabled is invalid usage:

if (info.rayQuery) consumers |= VK_PIPELINE_STAGE_COMPUTE_SHADER_BIT | VK_PIPELINE_STAGE_FRAGMENT_SHADER_BIT;ohao/render/scene/render_scene.cpp:465
Why

The alternative is a full TLAS rebuild every frame from an instance list rebuilt by walking the world — simple, and it needs no dirty tracking, but it pays the build cost for scenes where only a few objects move. Refit is much cheaper than a rebuild and degrades quality only gradually; the structural/refit split keeps the cheap path for the common case, a few transforms changing, and takes the rebuild exactly when the topology of what can be hit changed. What it costs is a flag that must be set by every edit that changes the topology: forget one and the refit silently traces a stale structure.

Base color, applied once

The closest-hit shader seeds `albedo` with the material's base colour and multiplies in the albedo texture when there is one — the glTF convention:

vec3 albedo = matColor.rgb;shaders/rt/pt_closesthit.rchit:137
if (diffuseTexIdx != 0xFFFFFFFFu) {shaders/rt/pt_closesthit.rchit:138

Albedo textures are uploaded as `R8G8B8A8_SRGB`, so the sampler returns linear values and no decode appears in the shader:

upload(model.materialTextureIndex, model.albedoTextures, VK_FORMAT_R8G8B8A8_SRGB,ohao/render/scene/model_upload.cpp:81

An untextured material is therefore its base colour, once, in the path tracer as in the G-buffer, which computes the same product and ignores the vertex colour:

albedo *= texture(textures[nonuniformEXT(albedoTexIdx)], fragTexCoord).rgb;shaders/includes/scene/gbuffer_body.glsl:138

No per-material fallback texture is created for it: `modelMaterials` uploads only the textures the model carries, and row 2 of the material table has no texture slot beyond the roughness/metal index. The G-buffer used to multiply in the vertex colour as well; primitives carry their colour as vertex colour and base colour both, so every primitive was shaded with its colour squared (a 0.5 wall at 0.25).

Key idea

The diffuse sentinel is the whole rule: a valid albedo index multiplies the base colour, `0xFFFFFFFF` leaves it alone. Any material that should look different in the path tracer than in the raster path has to say so in its own fields, not through a texture the loader adds.

Textures at their native size, base level only

Textures reach the hit shaders as separate bindless images, each at its own resolution and format, so there is no common extent to resample to. What the hit shaders cannot do is choose a mip: ray-tracing stages have no implicit derivatives, so the shaders sample the base level.

// count). Hit shaders have no derivatives: sample the base level (native resolution).shaders/rt/pt_closesthit.rchit:45

The images carry mip chains for the raster passes' benefit and the path tracer never reads them, so minification aliasing is a real source of noise on high-frequency textures; it is not something sampler state can recover.

The alpha test is opt-in. The any-hit shader multiplies the material's alpha by the albedo texture's alpha and ignores intersections below the material's cutoff, but every BLAS geometry is built opaque and the raygens add `gl_RayFlagsOpaqueEXT` to every `traceRayEXT` unless the scene has an instance with an alpha material. Such an instance is given `FORCE_NO_OPAQUE` in the TLAS, so only its triangles invoke the shader.

if (alpha < alphaRow.y) ignoreIntersectionEXT;shaders/rt/pt_anyhit.rahit:67

What an edit costs, and the one word RT GI still needs

There is no material-patching entry point: the material table is append-only, and a material is immutable once registered. The edits a caller can make are on the instance, and each has a distinct cost:

  • A **transform** change uploads one `InstanceGpu` row and refits the TLAS.
  • A **visibility** or **mesh** change uploads the row and forces a full TLAS build.
  • A **material list** change uploads the instance's 64-entry reference row and records

no TLAS work, because the TLAS entry is byte-identical.

RT global illumination still needs one value the material table does not hold. Its trace reads the bounce albedo from the instance, not the material row, as the RGB of a legacy word on `InstanceGpu`, loaded from the raw instance buffer at a byte offset the shared layout names and a `static_assert` in `rt_gi_technique.cpp` pins to the C++ struct:

const float3 albedo = asfloat(instances.Load3(slot * kInstanceGpuStride + kInstanceGpuGiAlbedoOffset));shaders/rt/gi_trace.slang:199
static_assert(offsetof(render::InstanceGpu, giAlbedoPacked) == shared::kInstanceGpuGiAlbedoOffset);ohao/render/rt/rt_gi_technique.cpp:18

Its alpha is a sign-and-magnitude packing — sign carries metallic, magnitude carries roughness, and a ±10 bias tags meshes with more than 100 vertices — produced on the host and uploaded to an instance word that nothing in `shaders/` reads; the trace loads three floats and stops short of it.

float packed = metallic > 0.5f ? -(roughness + 0.001f) : roughness;ohao/render/scene/model_upload.cpp:175

Contracts

  • Every TLAS instance's custom index is its render-world slot; the hit shaders index the instance table with it. Slots above 2^24 − 1 alias.
  • The triangle-slot stream is read with `gl_PrimitiveID`, so a mesh's BLAS must be a single geometry over exactly the mesh's index range. Splitting a mesh into several geometries makes `gl_PrimitiveID` restart per geometry and breaks the slot lookup.
  • A change to an instance's mask (visibility), mesh or existence must reach the TLAS as a structural change; only a transform-only change may refit.
  • The path tracer must be handed the scene buffers after `recordUpdates` each frame, never before: table growth and TLAS storage replacement change the handles.
  • Replaced TLAS storage, like replaced tables, is destroyed by the retire queue after `MAX_FRAMES_IN_FLIGHT` frames. Destroying it eagerly can free a structure an earlier frame is still tracing.
  • The closest-hit's albedo is the base colour, times the albedo texture when one is bound. For untextured materials the G-buffer applies the same base colour once; a change to either side alone makes those surfaces disagree between the two renderers, and any change to the closest-hit side moves the path-traced goldens.
  • All BLAS geometry is opaque and every raygen trace passes the opaque flag; an alpha-tested material will not cut out until both change.
