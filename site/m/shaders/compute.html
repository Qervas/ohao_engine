Compute shaders, and the target that builds them

`add_custom_target(shaders ...)` is declared without `ALL`, so building some other target alone compiles no SPIR-V. Every target that loads SPIR-V depends on it — the `ohao` CLI, the examples, `render_bench` and the rendering tests — so building any of those builds the shaders first.

add_custom_target(shadersshaders/CMakeLists.txt:121
add_dependencies(${name} shaders) # every example renders: never with stale SPIR-Vexamples/CMakeLists.txt:25

GLSL compute files are compiled by a glob; Slang files by a second one, one SPIR-V per `[shader(...)]` entry point:

"${CMAKE_CURRENT_SOURCE_DIR}/*.comp"shaders/CMakeLists.txt:12
file(GLOB_RECURSE SLANG_SOURCES CONFIGURE_DEPENDS "${CMAKE_CURRENT_SOURCE_DIR}/*.slang")shaders/CMakeLists.txt:82

SSAO on the raster path

SSAO is now Slang, `compute/ssao.slang`, with two entry points, so it compiles to two files, `compute_ssao.slang.occlusion.spv` and `compute_ssao.slang.blur.spv`, which `SSAOPass` loads by entry name:

!rtc::createComputePipeline(m_device, "compute_ssao.slang.blur.spv", "blur", m_blurSetLayout,ohao/render/deferred/ssao_pass.cpp:74

Both run 8×8 workgroups over the half-resolution image, and the host's `(N + 7) / 8` group count agrees. Its push block is `SSAOPush`, generated from `shaders/shared/layout.json` into Slang and C++ alike, and its sixteen noise rotations travel in that block rather than in a texture. The occlusion entry decodes the G-buffer's octahedral normal with its own copy of the decoder, which undoes the `* 0.5 + 0.5` remap `gbuffer.frag` applies at its call site:

const float2 f = e * 2.0 - 1.0;shaders/compute/ssao.slang:27
vec2 encodedNormal = encodeNormalOctahedron(N) * 0.5 + 0.5;shaders/includes/scene/gbuffer_body.glsl:221

The encoder returns [-1,1] and the G-buffer remaps it to [0,1] on write; every reader undoes the remap before decoding. Changing either side alone breaks the pairing silently, for SSAO, SSR and lighting at once.

It is off unless asked for:

bool m_ssaoEnabled{false};ohao/render/deferred/post_processing_pipeline.hpp:153

The model viewer, the `ohao_game` host, a live window session and a capture whose `post` list names `ssao` ask; render settings expose it as `ssao`.

pp->setSSAOEnabled(true);examples/model_viewer.cpp:186
.field("ssao", &RenderSettings::ssao).doc("Screen-space ambient occlusion")ohao/api/params.cpp:213

The kernel — a horizon search in the surface's tangent plane, eight directions of four steps from world-space G-buffer positions, then a 4×4 depth-aware blur — and its effect on the frame are the deferred SSAO unit's subject.

light_cluster: the froxel light lists

`compute/light_cluster.slang` has one entry point, `build`, so it compiles to `compute_light_cluster.slang.spv`, which `LightClusters` loads by that name:

if (!rtc::createComputePipeline(m_device, "compute_light_cluster.slang.spv", "build", m_setLayout,ohao/render/deferred/light_clusters.cpp:73

It runs one 64-thread workgroup per froxel, 3,456 workgroups in a one-dimensional dispatch, and imports its `LightGpu` record, its `ClusterPush` block and every `kCluster*` constant from the generated `shared.layout` module, the same module `deferred_lighting.slang` and the shared light loop import. The kernel and why its lists leave the lit image unchanged are the deferred clustered-lighting unit's subject.

[numthreads(kClusterGroupSize, 1, 1)]shaders/compute/light_cluster.slang:33

cull/: the draw lists and the depth pyramid

GPU culling's modules sit in their own directory, `shaders/cull/`, and compile by the same Slang glob. `instances.slang` has five entry points, so five files, which `GpuCulling` loads by entry name with one shared set layout and push range:

{"cull_instances.slang.classifyMeshlets.spv", "classifyMeshlets", &m_classifyMeshlets},ohao/render/deferred/gpu_culling.cpp:90

`classify` and `scatter` run one thread per draw in workgroups of `kCullGroupSize` (256), `classifyMeshlets` and `scatterMeshlets` (the mesh-shader fallback) one per meshlet entry, and `scanBlocks` a single workgroup of the same size; the host dispatches `(items + 255) / 256` groups. `common.slang` has no entry point: it is the module of culling tests that `instances.slang` and `meshlets.slang` both import. `meshlets.slang` is not compute: its task, mesh and pull entries are the G-buffer's meshlet geometry stages, loaded by `GBufferPass`. `hiz.slang`'s `fromDepth` and `downsample` build the max-depth pyramid in 8×8 workgroups, one dispatch per level. Their push blocks, `CullPush` and `HiZPush`, and the `DrawRecord` they read come from `shaders/shared/layout.json`. The algorithm — phases, prefix-sum compaction and the occlusion test — is the GPU culling unit's subject.

[[vk::push_constant]] ConstantBuffer<CullPush> pc;shaders/cull/instances.slang:38

dlss_tonemap: display space, behind a build gate

The last is the DLSS Ray Reconstruction display pass, dispatched after RR writes its denoised HDR image, with one descriptor set per frame in flight:

m_dlssRR->tonemap(cmd, frameSlot, m_dlssColorOutView, m_outputView, m_width, m_height);ohao/render/rt/path_tracer_render.cpp:683

That call site is inside `#ifdef OHAO_DLSS_ENABLED`, and so is the whole of `dlss_rr.cpp`, the only translation unit that names the `.spv`.

#endif // OHAO_DLSS_ENABLEDohao/render/rt/path_tracer_render.cpp:687
#ifdef OHAO_DLSS_ENABLEDohao/render/rt/denoise/dlss_rr.cpp:5

The option is on only when the NGX static library is on disk, and `.gitignore` excludes the directory that holds it: `tools/fetch_dlss.py` downloads the pinned SDK files into `external/DLSS`. A clone without them compiles the file empty; the `.spv` is still produced by the glob, and nothing loads it.

set(OHAO_DLSS_STATIC_LIB "${CMAKE_SOURCE_DIR}/external/DLSS/lib/Windows_x86_64/x64/nvsdk_ngx_s.lib")CMakeLists.txt:66
external/DLSS/.gitignore:85

Where it does run, it takes `RGBA16F` linear to `RGBA8` with the path tracer's curve: ACES at 0.5 exposure, then gamma 2.2, the transform the tracer's own output and `nrd_compose` apply, so every denoiser's frame is displayed alike. Nothing else happens to the frame, and nothing feeds back into the trace.

imageStore(ldrOut, pix, vec4(pow(ACES(hdr * 0.5), vec3(1.0 / 2.2)), 1.0));shaders/compute/dlss_tonemap.comp:20

Contracts

  • The `shaders` target is not in `ALL`; only the targets that declare `add_dependencies(... shaders)` rebuild SPIR-V before they build, and a new target that loads SPIR-V must declare it too. Compilation is by glob, so adding a `.comp` or `.slang` yields SPIR-V and no wiring: a loader must ask for the path-flattened name, `compute/<name>.comp` → `compute_<name>.comp.spv`, and a Slang module with several entry points `compute_<name>.slang.<entry>.spv`.
  • `compute_dlss_tonemap.comp.spv` is named only from inside `#ifdef OHAO_DLSS_ENABLED`. Without `external/DLSS/` at configure time the pipeline is never created, so any claim that it reaches a frame is a claim about a machine with the NGX SDK vendored in.
