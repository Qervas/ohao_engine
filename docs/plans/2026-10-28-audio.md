# Audio (Sub-project 11) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In `blockout_play.scene.json`, the fight is mixed:
- buses with caps and priorities, ducking under the player's own fire;
- `dead` and `won` snapshots;
- reverb zones (the room, the open air);
- graded occlusion behind cover;
- every sound at its step's time on the audio clock.

What plays is decided in the step as a **voice schedule**. Every host builds it, so the same fight
gives the same schedule; agents read it (`audio.info`) and set the mix for tests (`audio.mix`). The
mix cost is gated, and Frank signs the mix off by ear.

**Architecture:**
- **The schedule** (`ecs/audio_schedule`): a simulate system, the step's last. It reads the
  physics, combat and animation logs and the listener at the step, and writes play, steal, drop,
  bus, snapshot, zone, occlusion and stop commands to a log. Its state (voice table, round robin,
  ducks, snapshot, zone) rides in the World's `SnapshotHook`. It is never saved or hashed.
- **The data:** one `.audio.json` per game (sounds with bus, priority, shape, `holdMs`, send;
  buses with caps; ducks; snapshots; reverb presets), named by the saved singleton `AudioMix`. A
  saved `ReverbZone` comes from the scene or the level hint `verb`.
- **The mixer** (`ohao/audio/AudioSystem`, miniaudio 0.11.21):
  - buses as nested `ma_sound_group`s, each with a gain, a low-pass and a reverb send;
  - our own Freeverb-style node on the reverb return;
  - voices from a preloaded, decoded bank;
  - start times in PCM frames;
  - deviceless rendering for tests and benches.
- **The player** (`runtime/audio_player`): a window host's bridge. It reads the schedule by cursor
  each frame and plays each command at its step's engine time plus a one-step horizon. It replaces
  `runtime/footsteps` and `runtime/combat_sounds`, which are deleted.

**Tech Stack:** C++20, EnTT, miniaudio 0.11.21 (in-tree, public domain/MIT-0), simdjson (the
`.audio.json` reader, as `.animgraph.json`), Python 3 (sound generators in `tools/audio/`,
harnesses).

**Spec:** `docs/specs/2026-10-28-audio-design.md`. It is binding once Frank accepts it; its
PROVISIONAL rulings 1–6 are designed to, and its OPEN rulings 7–20 are the recommendations until
ruled.

## Review Focus

1. **Two steps in one frame, the second a round restart:** the `stop: world` and the restored
   step's commands are applied in order, the old voices fade, and nothing from the abandoned
   timeline plays (Task 3, `t28_restart_like_start`; `t29_player_clock`).
2. **A bus cap and the global cap reached in the same step, and a voice stolen in the step it would
   end:** one victim each, the same choice every run (Task 3, `t28_priority_and_steal`).
3. **A snapshot change mid-blend** (`dead`, then the restart before the blend ends): the new blend
   starts from the current levels without a jump (Task 1, `t26_snapshot_blend`; Task 3,
   `t28_snapshot_from_round`).
4. **The listener exactly on a zone's face, and two overlapping zones of equal priority:** one zone,
   chosen by id the same way every run (Task 2, `t27_zone_containment`).
5. **A bank sound with no file in any folder** (a missing local recording, a typo): the schedule
   still writes the command, and the player skips it with one warning per name, never a crash or a
   file opened on a play (Task 3, `t29_preloaded` missing case).
