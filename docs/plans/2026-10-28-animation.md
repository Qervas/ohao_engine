# Animation (Sub-project 10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In `blockout_play.scene.json`, two skinned enemies replace the boxes: they run, aim, shoot, flinch and die, and their handling sounds come from animation events. The player holds animated arms and a rifle (idle, fire, reload in exactly `Weapon.reloadTime`, ADS, sprint). Everything renders validation-clean in raster and RT, with shadows, GI, the path tracer and motion vectors seeing the deformed mesh. Culling and determinism tests cover skinned meshes, and skinning has a gated budget.

**Architecture:**
- **Step state.** Saved animator state is integers, advanced by whole steps: per layer, the state, its steps, and the fade.
- **Simulate system.** An `animation` simulate system after `combat` (drivers → transitions → events into a log) owns all gameplay-visible animation.
- **Sync system.** A `pose` sync system after `view_model` samples clips at `(steps + alpha)` into runtime palettes and attachment `RenderPose`s: presentation only.
- **The renderer:**
  - each skinned instance gets its own range in the shared vertex arena, its own meshlet copy and its own updatable BLAS;
  - three passes before culling and the TLAS update: `skin` (compute), `skin.bounds` (deformed meshlet spheres and draw AABBs, no atomics) and `rt.blas.refit`;
  - previous positions in a new stream give limb motion vectors.
- **What stays unchanged:** every consumer (G-buffer, CSM, meshlets, path tracer, ray queries) keeps finding vertices through `InstanceGpu.mesh` as today.

**Tech Stack:** C++20, EnTT, simdjson (the glTF reader), Vulkan 1.3 (compute, `VK_KHR_acceleration_structure` update), Slang for new shaders, Python 3 (the test-rig generator, harnesses), Blender 5.2.2 (the arms rig script; its test skips without Blender).

**Spec:** `docs/specs/2026-10-28-animation-design.md` (binding once Frank accepts it; its PROVISIONAL rulings 1–6 are designed to, its OPEN rulings 7–18 are the recommendations until ruled).

## Review Focus

1. A transition and a clip event on the same step, and an event exactly at a looping clip's end: each emitted once, in step order (Task 1, `t23_events_once_per_crossing`).
2. A snapshot taken mid-fade, restored and stepped: the same `Animator` bytes, events and `world.hash` as the uninterrupted run (Task 1, `t23_restore_mid_clip` fade case).
3. A skinned instance created and destroyed in one frame, and an enemy entity removed mid-fight: its arena range, previous-position slice, meshlet copy and BLAS are retired and never read after free (Task 1, `t24_two_instances_two_poses` destroy case; validation clean under `OHAO_VALIDATION=sync`).
4. An arm swung outside every bind-pose bound: drawn, in the cascades, and hit by RT shadows, GI and the path tracer (Task 1, `t24_cull_parity_skinned`, `t24_rt_sees_the_pose`).
5. A placement mid-run (restart, `player.teleport`): no motion vector across the jump, the previous palette reset (Task 1, `t24_motion_vectors_of_a_limb` placement case; Task 2 again on the enemies).
