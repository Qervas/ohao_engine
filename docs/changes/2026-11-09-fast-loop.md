# The edit loop in seconds: tests, build, goldens

**Spec:** `docs/specs/2026-11-08-system-design.md`, 4.2 (the binding headers made from the shaders' reflection at
build, as `docs/plans/2026-11-09-step2-delete-and-unify.md` 2e planned) and 4.9 (every dependency pinned, dead ones
deleted); AGENTS.md, "Every gate runs in seconds" (Frank, 2026-11-09). **Status:** built, three local commits
(`2a691d0e`, `457869f5`, and the goldens' one).

## 1. Summary

A one-line change used to cost about 100 s of tests, and a shader edit 19 s more before any test ran. Now the whole
check (build, `ohao doctor`, every gate) takes 9.8 s on an unchanged tree. A shader edit builds in 0.9 s, and a
renderer `.cpp` in about 2 s.

## 2. What was built

- **The tests, one process each** (`2a691d0e`). Every GPU check is now one `ohao serve` process
  (`tests/common/ohao_serve.py`: one device, the programs compiled once, the scenes loaded in turn), rendering at the
  fewest pixels and samples that hold its bars. The five temporary tests are deleted, with `tests/serve/` and the
  caustics CPU twin that only they used.
- **Shader rules with depfiles** (`457869f5`). Each entry's compile also writes its reflection and the files it
  read (`slangc -reflection-json`, `-depfile`). A shader is rebuilt when its own file or one it imports changes; before,
  every rule depended on every `.slang`.
- **The binding headers written by the build** (`457869f5`). `tools/gen_bindings.py --manifest` merges each file's
  entries' reflection and writes `ohao/render/shader_bindings/*.hpp`, only those whose text changed. The headers
  can no longer go stale, so `--check` is only the scan for typed binding numbers. `ohao_gpu_vulkan` and
  `ohao_renderer` depend on the `shaders` target, so even a first build compiles them against current headers.
- **The configure** (`457869f5`):
  - The dependencies are re-checked only when their declarations change: a hash of `CMakeLists.txt`,
    `external/cmake/` and the options that pick them (`OHAO_DEPENDENCIES_POPULATED`). Otherwise
    `FETCHCONTENT_FULLY_DISCONNECTED` is on.
  - stb is pinned to the commit already in use.
  - `slangc -v` runs once per binary.
  - googletest and `ohao_gtest_main` are deleted: no suite used them. So are `tinyfiledialogs.cmake` and
    `json.cmake`'s second `FetchContent_MakeAvailable`.
- **The goldens** (this commit). One `ohao serve` renders all five at 640x360, the size they were already stored and
  compared at. They used to be five `ohao run` processes rendering 1920x1080, which the harness then shrank to
  640x360. The manifest now names `scene` and `capture` (render.capture's parameters) instead of a command line. The
  five goldens were regenerated.

## 3. Bugs found and fixed

- **Every shader rebuilt on any shader edit.** Each SPIR-V rule had `DEPENDS ${SLANG_SOURCES}`.
- **The binding check recompiled every shader.** It took 5.8 s on every `check.py` run, whether or not a shader had
  changed.
- **stb tracked `master`.** Every configure fetched from GitHub, about 0.8 s.
- **Every reconfigure recompiled NRD and relinked all 14 programs.** NRD's `CMakeLists.txt` rewrites
  `Shaders/NRDConfig.hlsli` at each configure, and every NRD shader includes it. `external/cmake/nrd.cmake` now gives
  the header its old time back when its text is unchanged (`file(COPY)` keeps a file's time).
- **A dependency cycle during the work.** A separate `shader_bindings` target ordered the shader compiles after
  the header step that reads their output. The header step now lives in the `shaders` target.

## 4. Spec corrections

None. 4.9's "stb on `master`" and "`tinyfiledialogs.cmake`" are done.

Nothing changed in what the build produces:

- **SPIR-V:** byte-identical for all 77 after the depfile and reflection change.
- **Binding headers:** the build's first run wrote them byte-identical to the committed ones.

The goldens:

- **Same image either way:** each of the five renders byte-identically through `ohao run` and through one serve
  process.
- **Path tracer:** at 640x360 it is exact run to run (five renders: three processes, then two reloads in one
  process). Its tolerance stays at `max_abs` 1 and 0.0005.
- **Planted bug:** 1% brightness in `displayPixel` failed all five, with 75 to 84% of the pixels differing.
- **Old against new:** the regenerated goldens differ from the old ones by a mean of 1.0 to 3.9 levels for the
  deferred scenes and 13.7 for the path tracer, which was averaged nine pixels to one before. Side by side, they show
  the same scenes.

## 6. Known gaps

- **`check_material`'s process exit waits about 1.6 s.** `vkDestroyDevice` waits on a lock while a thread of the
  NVIDIA driver compiles a shader in the background (`libnvidia-gpucomp`). It is not OHAO's code, and it happens
  only after the check's whole sequence. Skipping the device destroy alone cut the wait to 0.9 s; the rest is the
  driver at process exit. Skipping all teardown at exit, as the fault path does, would remove it, but that changes
  how every program shuts down: not done, Frank's call.
- **The first GPU program after an idle period pays about 2 s.** The laptop powers the GPU off when idle (runtime
  D3, fine-grained); waking it costs that. Back to back, the wake is paid once per run.
- **A `.cpp` edit relinks 14 programs.** Each takes 0.1 to 0.5 s with `ld.bfd`; mold or lld is not installed.
- **A shader edit still reconfigures (0.6 s).** The configure reads the entry points, so a new one gets its rule.
- **Windows untested.** The depfiles, the header step (which needs Python at configure) and the dependency hash are
  not tried on Windows; the last Windows build was 2026-11-05.
