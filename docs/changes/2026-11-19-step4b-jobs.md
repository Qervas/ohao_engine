# Step 4b: jobs, waves, Jolt on jobs, engine modules, the frame packet and the render thread

**Spec:** `docs/specs/2026-11-08-system-design.md`, 4.3, 4.5 and 5 (step 4); the engine modules design
`docs/specs/2026-11-18-engine-modules-design.md` (rulings R1-R7); plan `docs/plans/2026-11-18-step4b-jobs.md` (its
as-built notes hold every number below, with its rounds). **Status:** built 2026-11-18 to 2026-11-19 (`8458f603` to
`2c71aa14`): 4b-0 to 4b-6b on Linux (Fedora 45, GCC 16) on `step4b-jobs`, then, after the GSP firmware crashes there,
the Windows port and 4b-7 to 4b-9 on Windows 11 (MSVC 14.52) on `windows-port`. Closed with four items owed (section 6),
held by Frank's GPU rule of 2026-11-19: until the GPU's health is known it runs only the gates.

## 1. Summary

The engine ran on one unpinned thread of a 32-thread i9-13900HX. It now has one job pool of its own shaped to that CPU;
every system declares what it touches and the step runs in waves, with the same `world.hash` at any thread count and
in any order within a wave; Jolt runs on that pool; per-entity work inside systems is split with `parallelFor`; the
engine is nine modules, each deletable by proof; the renderer reads a world only through a frame packet; and a render
thread can record frame N while the game thread steps N+1. The crowd (the play scene with a 1,000-box pile and 64
enemies) steps in 0.81 to 0.82 ms at 31 threads against 2.49 at one. The render thread is off by default: in a play
window it did not lower the look latency.

## 2. What was built

- **The measures (4b-0):** the crowd (`tools/bench/bench_world.hpp`), `physics_bench --only` and `crowd_step_ms`,
  `render_bench crowd_1080p`, `ohao run --frames K --uncapped` (frame, simulate, sync, record, GPU, hash), `job_bench`.
- **The pool (4b-1, `ohao/core/jobs`):** the topology (Linux: `cpu_core`/`cpu_atom`; Windows:
  `GetLogicalProcessorInformationEx`), a Chase-Lev deque per thread and priority (capacity 4,096; a full one runs the
  task inline), frame and background priorities, a 50 us spin then a sleep on `std::atomic::wait`, waits that help, `jobs::Graph`,
  `parallelFor`, `background`, `copy` (4b-9) and `Dedicated` (4b-8). Workers pinned to their core class's set, SMT on,
  E-workers on frame tasks, all 31 threads: each measured against the alternatives.
- **The helpers on the pool (4b-2):** the cooker, the meshlet normals, the PNG encoder and the RT pipeline's compile;
  their `std::thread`s deleted. `check.py` refuses `std::thread`, `std::jthread` and `std::async` outside the pool, the
  RPC reader and the present waiter.
- **Jolt on the pool (4b-3):** `JoltJobs : JPH::JobSystemWithBarrier` (`physics/private/backend/jolt/jolt_jobs.*`,
  without RTTI); a step's contact events sorted by (body 1, body 2, sub-shape 1, sub-shape 2, type); a step under 100
  active bodies inline. `enableMultithreading`, `workerThreads` and `JobSystemThreadPool` deleted.
- **The declarations (4b-4):** `SystemDecl`, `SignalEffect`, `ComponentType` (`ecs/system.hpp`); systems are
  `fn(SystemContext&, dt)`; `SystemOrder` deleted. Every engine, slice and sample system declared, every EnTT
  connection through `World::onConstruct/onUpdate/onDestroy/disconnect` with its effect (`check.py` refuses a raw
  `on_*<` outside `world.hpp`); the install check; the check mode (`OHAO_ACCESS_CHECK=1`).
- **Waves (4b-5):** runs of consecutive systems that conflict in nothing; `EventStage` per system, flushed in serial
  order; `OHAO_WAVE_ORDER=reverse`, `OHAO_WAVE_INLINE_US`; `replay_test` runs one leg at one thread in order and one at
  every thread, reversed, every system dispatched, in check mode.
- **Parallel inside systems (4b-6):** pose's evaluation, the enemies' sight rays, physics' write-back and
  `syncBodies`, the transforms' root matrices; `StepTempAllocator` for Jolt's contact buffer. The crowd's budgets
  `crowd_step_ms` 1.2 and `crowd_sync_ms` 0.30.
- **Engine modules (4b-6b):** `ecs::Module`, `Services`, `installModules`, `ohao_add_module`; the modules ecs, visual,
  animation, physics, audio, footsteps, vfx, level and world_render; `engine::install(world, services, only)`;
  `installRendering` deleted, `World::World()` installs nothing; `tools/check_layers.py` (configure and every
  `check.py`): levels, declared dependencies, `private/`, cycles, and each module deletable (R5 static). `world.hash`,
  the snapshot's columns and saves walk types by name (R2's one deliberate change of every hash).
- **R1's edit loop:** EnTT's registry header for `entt.hpp`, the core's components only where named, a precompiled
  header per engine target, each component's storage compiled once in its module's `storage.cpp`.
- **The Windows port** (`4878202e`, `bd667155`, `cfa7be73`, `7368537d`): MSVC flags, per-platform code, the game
  module as a DLL with a generated import list, NRD's DXC, the event-log GPU-fault gate, the no-op build.
- **The frame packet (4b-7, `ef2aa6b4`):** `render::FramePacket`, filled by world_render's `render_extract`, `vfx_draw`
  and the hosts, applied and emptied by `VulkanRenderer::render(packet)`.
- **The render thread (4b-8, `131415ce`, `2c71aa14`):** `render::RenderThread` on a `jobs::Dedicated` thread,
  `publish()` double-buffered, `run(fn)`, `waitForGpu()`, the owner check in every build, `--render-thread on|off` in
  `ohao run`, `ohao serve`, `ohao_game` and `feel_bench`, off by default.
- **Loads on the pool (4b-9, `961c1ebf`):** `jobs::copy` for the texture uploads and `registerMesh`'s staging,
  `registerMesh`'s checks as a `parallelFor`, `modelKey`'s file touches on the pool.
- **The TLAS guard (`e7bafba8`):** after each frame's TLAS, while a retired BLAS waits, a live slot naming one logs the
  slot and the address and aborts.

## 3. Bugs found and fixed

- **The job pool's publication** (4b-1, TSan): `push` published by a fence; now a release store of `bottom`.
- **An adapter task outliving its step** and its backend (4b-3, TSan): the adapter waits for its tasks after each step.
- **Gaps the install check found** (4b-4): spin after fly_controller, instantiate before transform, pose and
  view_model after transform, the order the hosts already had, now declared.
- **`ohao serve`'s "free(): invalid pointer" at exit** (4b-4, TSan run): its signal effects were freed before the
  systems disconnecting from them; the members are reordered.
- **54% of the workers' samples were page faults** (4b-6): Jolt's contact buffer (65,536 x 864 B, 57 MB) did not fit
  its 10 MB temp block and was mapped and unmapped every step (2.7 M faults in 1,800 steps; 37 k after).
- **`skinPalette` 304 -> 571 ns** under the engine-wide machine flags (4b-6b build 3): written out column by column,
  175 ns, bit-identical.
- **Engine state a game read** (Windows port): `log::detail::g_threshold`, found by `gen_game_imports.py`; a game reads
  `log::level()`.
- **NRD's SPIR-V from the Vulkan SDK's DXC** emitted `SPV_KHR_compute_shader_derivatives`: 40 validation messages;
  ShaderMake's pinned DXC now. Three discarded `[[nodiscard]]` results now log their failure.
- **A mesh released while its user's create waited in the packet** (4b-7 review): apply skips a change whose mesh is
  gone, and an update of an id with no slot creates it.
- **A replaced scene hashed by its process's history** (`b080c939`): a replace load kept the creation-order counter,
  the audio schedule's bank, physics' backend handles and contact-end events, combat's, vfx's and the input's state,
  and the step count. The session restores the installed world's snapshot first.

## 4. Spec corrections

- **System design 4.3, 4.5, 4.8 and step 4** now say what was built; "no job system yet", "Jolt stays on the calling
  thread" and the streamer sentence are gone. 4.2's install is `engine::install`.
- **An emplace or remove of a declared component is a write**; only creating or destroying entities (or a subsystem
  with its own registry use) makes a system exclusive (the plan: every structural change). Waves are runs of
  consecutive systems in the serial order. Resources are declared and used for conflicts, not checked at run time;
  the reversed leg is their check.
- **The modules' public headers stay at their roots,** private ones under `private/` (the plan said `public/`).
- **`RenderScene` keeps its slot allocator** and maps the writer's ids to slots (the plan: the allocator moves to the
  writer), so slots and goldens do not move.
- **`RenderThread::run(fn)` runs `fn` on the caller** while the render thread waits (the plan: on the render thread),
  so a load keeps helping the pool and nothing crosses a thread-local.
- **The owner check is on in every build** (the plan: Debug); no Debug build runs here and it costs nothing measured.
- **Play windows default to the render thread off** (the plan: on), by the plan's own latency rule.

## 5. Results

Linux numbers (4b-0 to 4b-6b) and Windows numbers (the port, 4b-7 to 4b-9) are different compilers and OSes and are
not compared with each other. Ranges are the min-max of alternated rounds' medians.

**The pool's costs** (Linux, 31 threads): spawn to run 0.34-0.35 us (p95 0.49); a contended steal 169-171 ns; a wake
2.65-2.71 us; 1,000 chunks of about 2 us 94.5-94.8 us against a 1,954 us loop (20.6x).

**Jolt on the pool** (Linux, ms): boxes1k 2.40-2.41 at 0 workers, 0.75-0.77 at 8, 0.79 at 30; the crowd 2.69-2.70 at 0,
0.98-1.01 at 8, 1.02-1.03 at 30. Hashes identical at every count.

**The crowd after 4b-6** (Linux, ms):

| Threads | 1 | 3 | 5 | 9 | 31 |
|---|---|---|---|---|---|
| the crowd's step | 2.49 | 1.37-1.44 | 0.98-1.03 | 0.82-0.88 | 0.81-0.82 |
| its sync | 0.48 | 0.29-0.31 | 0.20-0.24 | 0.19-0.21 | 0.19-0.20 |
| boxes1k | 2.22 | 1.17 | 0.75-0.81 | 0.64-0.66 | 0.58 |

Against the 4b-0 baseline (the crowd's step 2.632-2.674 ms): 4b-5 1.024-1.086, 4b-6 0.822-0.943. No `physics_bench`
scenario slower beyond the spread at any part; the small scenarios 0.1-5.7% slower than base at the default thread
count and equal at `--threads 1` (the process being multi-threaded).

**Helpers** (Linux): Sponza's first cook 5,581-5,673 -> 5,036-5,107 ms, its 66 files byte-identical; kit2k's load
89.0-90.3 -> 88.3-89.4 ms.

**The render thread** (Windows, the crowd uncapped, 3 rounds): at 320x180 the frame 2.263-2.295 ms off, 1.677-1.689 on
(the larger of simulation and recording 1.672-1.687, their sum 2.149-2.166); at 1920x1080 6.936-6.973 off,
6.951-6.969 on. The owner check: the crowd's record 0.519-0.538 ms with it, 0.526-0.538 without (5 rounds).

**Look latency** (Windows, `feel_bench` immediate, median): scale 1 off 6.79, 6.86, 6.89 ms; on 21.04 (an outlier),
6.85, 6.96; scale 0.5 off 5.00.

**Loads** (Windows, 2 processes of 4 alternated rounds): Sponza's arrival 145.6-165.6 -> 104.4-140.0 ms, the helmet's
47.6-58.0 -> 42.8-47.8 ms; captures byte-identical; the release loop's memory unchanged.

**The frame packet** (Windows, `render_bench`, 3 rounds against `cfa7be73`): every scene within the spread but
`play_anim_1080p` 1.67 -> 2.25 ms GPU, which now draws the world's camera every frame as a window does (held fixed:
1.66-1.78).

**The edit loop** (Windows, `-j12`, AGENTS.md): an unchanged tree 0.29-0.30 s; a shader 3.0-3.3 s; a system `.cpp`
4.4 s; a renderer `.cpp` 4.8 s; a field in `animation/components.hpp` 20-23 s, in `physics/components.hpp` 39 s.

**Determinism:** the crowd, boxes1k and events_1k hash the same at 1, 30 and 31 threads, natural and reversed, every
system dispatched, in check mode; `replay_test` 13/13 on Windows (12 + the replace load); on Linux its checkpoints held

**Planted, each caught:** `take`'s seq_cst fence removed (3,202 tasks twice and 3,202 lost at 10^7); one wake in 1,000

undeclared system; an undeclared static (the reversed leg); a float sum in completion order; a raw signal; an include
of an undeclared module and a cycle (P1-P5); the session naming a module's install; a submit from the game thread
(the validation layer); a renderer call outside `run` (the owner check); each of the 5 parts of the hash fix removed;

Synchronization validation silent with the thread on, a hidden-window `serve` included; captures with it on
byte-identical to off.

**The close:** `check.py` on `2c71aa14` (the default change): build, `ohao doctor` and 6 gates (`check_validation` 21,

## 6. Known gaps

- **Owed, held by the GPU rule:** `feel_bench` runs 9-12 (run 8 ended in the fault below); the visible resize run
  under synchronization validation; the 1080p step question below.
- **The 1080p step:** with the thread on, the GPU-bound crowd's step reads 2.68 -> 3.90 ms while its frame is unchanged.
  Not explained.
- **TSan for 4b-7 to 4b-9:** not run; MSVC has no thread sanitizer and Linux is not built now. 4b-1 to 4b-6's TSan
  reports were all inside Jolt, the kinds of a control run on Jolt's own pool.
- **`asset_bench.py` reads `/proc`** and does not run on Windows.
- **R1's 10 s is not met:** a field in `animation/components.hpp` takes 20-23 s and in `physics/components.hpp` 39 s
  (Windows; throughput-bound). The modules design's other open
  items: `engine.modules` over the API (R6) is not built, R7's measurement is not made, R5's dynamic proof (the engine
  built with each leaf module removed) is not recorded, and `docs/agents/ohao-cli.md`'s component table and the
  `add-component` skill do not yet name the modules' files.
- **Today's scenes gain nothing from waves:** the play scene's and the crowd's simulate waves are
  `[fly_controller] [spin] [physics] [combat] [animation] [audio_schedule, vfx]`, the one wave of two run inline.
- **Jolt's barrier wait** is the crowd's largest step cost after 4b-6; making it help is the adapter's next work.
